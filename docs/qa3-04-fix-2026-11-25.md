## 方案与实际变化

原问题不是 Python 的公式算错，而是 API 没有交付已算好的分数，页面再次使用各自运行时 lowercase 计算。现在保留 Python 3.12 的现有规范化与 `recruiting.matching.score`，两类在线页面共同使用它的结果。**没有对两个字符加入特殊映射，也没有重置用户已有数据库。**

| 位置 | 修改 |
|---|---|
| `recruiting/jobs.py` | 原推荐服务支持只读 draft skills；新增 `ranked_applications` 复用原申请人打分、权限和同分规则，给全部所属申请提供确定顺序。 |
| `recruiting/api.py` | candidate/employer bootstrap 输出权威 `score` 与 `rank`；资料/职位/状态修改返回新 `snapshot`；新增 Candidate-only 的只读 `matching-preview`。 |
| `recruiting/present.py` | 将分数和排名交付页面；技能在展示边界也按后端规则规范化，避免 JS 对已保存值再次 lowercase。 |
| `shared/match.js` | 新增 `fromServer` / `byServerRank`，仅校验、投影 API 事实；缺少分数/排名即报错，不回退到本地猜分。保留旧计算器供 standalone/demo。 |
| `candidate/assets/matchwork.js`、`recruiter/assets/recruiter.js` | 在线模式消费 API 分数及 rank，不再计算或比较匹配文本；保存立即接受 snapshot，导航/焦点/可见性及可见页面每 5 秒刷新。 |
| Candidate 页面及 Recruiter Applicants/Jobs/Dashboard | 接入当前页面的刷新订阅，更新列表、详情和主 Dashboard；保留本地筛选、选中项、Saved 状态；未保存草稿会暂停后台采纳。 |
| `candidate/profile.html` | 原技能预览改用服务端返回的 draft score 与 `baselineScore`；预览不保存草稿，真正保存后立即更新结果。 |
| live 技能编辑器 | 不用 JS lowercase 去合并两个后端会区分的输入；实际规范化和去重仍由后端执行。 |

Candidate 的 API 顺序为 `(-score, title.lower(), job_id)`；Employer 每个职位的申请顺序为 `(-score, display_name.lower(), candidate_id)`。All-jobs 视图仅在最后增加 application ID 以稳定同一候选人的多次申请。API rank 是后端已有顺序的序号；前端筛选后只保留该顺序，不重新用 JS 文本或 Number ID 破同分。

## 两个反例现在的真实结果

采用已有后端规则，两个初始样例的正确期望均为 0：

| candidate / required | 后端 API | Candidate 页面 | Employer 页面 |
|---|---:|---:|---:|
| `["\u1C89"]` / `["\u1C8A"]` | 0 | 0 | 0 |
| `["\uA7CB"]` / `["\u0264"]` | 0 | 0 | 0 |

保存改为实际命中的技能后，分数更新为 100；招聘方修改要求为不匹配技能后为 0，改成空要求为 100。匹配和同分顺序均通过 API 和实际 DOM 核对。两端接口继续只返回调用者允许访问的数据，新预览接口对匿名为 401、Employer 为 403，拒绝非法技能且不修改 DB。

## 测试变化没有删除或屏蔽失败

原始函数级对照验证的是两个独立计算器，这已不是在线架构的打分链路：

- 正式 `matching_parity.py` 现在通过真实认证 Flask JSON API，交付结果给真实产品 `fromServer`，对照前端收到的分数及顺序。内存关系数据库保持大语料隔离；固定算例仍有独立期望。
- 原对照源码保留在 `legacy_matching_comparison.py` / `legacy_unicode_probe.py`，可用 `--legacy-functions` 运行。两个运行时的原始 lowercase 差异仍明确返回 1，不被伪装成算法函数已一致；该计算器只供离线 demo。
- 正式 `unicode_version_probe.py` 默认执行两个反例的 API 链路；`--browser` 执行完整部署页面回归并写新结果。两者均已退出 0。
- 新浏览器回归把旧 JS 打分、规范化和匹配排序函数替换成“调用就抛错”的保护函数。实际浏览器操作结束仍为 **0 次调用**，防止以后误加本地回退。
- CI 保留 Unicode 门禁，不使用 skip/xfail/continue-on-error；门禁改验真实链路，另加入完整在线 authority/refresh 回归。
