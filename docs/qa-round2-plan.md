## 测试范围

| 方法 | 执行内容 |
|---|---|
| 需求分区与边界测试 | 按需求列正常、临界、非法输入。重点覆盖技能空值、重复项、类型和长度边界，时间与时区，资源 ID，以及不同身份的请求。 |
| 独立计算预期结果 | 根据 spec 手算匹配分、向下取整、空职位要求得分与同分排序；检查求职者和招聘方两端结果。 |
| 失败后的数据状态检查 | 对非法创建/更新、重复投递、无资格预约等拒绝操作，检查响应以及相关记录、关联关系和其他记录是否保持正确，验证没有部分写入。 |
| 可复现的模糊测试 | 生成结构化技能列表、时间字符串和异常 JSON；限制运行规模，保存随机种子、失败输入、预期与实际结果，并尽量缩小失败样例。不得吞掉意外异常。 |
| 变异测试 | 在隔离副本中小范围故意改错打分、权限、预约资格或重复判断，验证用例能否检出。记录有效变异、检出和存活情况；区分等价变异及运行错误。不得把变异带回正常工作区。 |
| 蜕变测试 | 根据 spec 验证技能顺序、重复项、大小写和首尾空白变化不改变分数；固定职位要求，在合法输入范围内给求职者增加匹配技能，分数不应下降。 |
| 静态检查与请求验证 | 检查权限、输入校验、SQL 使用、输出渲染和事务处理。用未登录、求职者、所属招聘方、其他招聘方实际请求验证可疑点，覆盖越权访问及简历隐私。静态告警需核实后再作为缺陷报告。 |

## 执行顺序与工具

1. 补需求—用例对照表，测分支覆盖率，找出未覆盖的关键分支；覆盖率用于定位缺口，不作为正确性的唯一证明。
2. 完成需求、边界、独立预期和数据状态检查，再补蜕变、模糊及安全测试。对投递和预约可补合法/非法操作序列测试。
3. 对核心逻辑做有限范围变异测试，分析未检出的错误并补强用例。
4. 回归新增与受影响的用例，并在最终版本执行现有 Docker、浏览器、HTTP、并发和持久化验收，避免重复无效运行。

可考虑 Hypothesis（属性和输入生成）、coverage.py（分支覆盖率）、mutmut（变异测试，需 WSL/Linux）；结合现有环境选择，不强制引入全部工具。

Skills 为可选辅助，不是验收条件：浏览器测试可参考 [webapp-testing](https://github.com/anthropics/skills/blob/main/skills/webapp-testing/SKILL.md) 或 [playwright](https://github.com/openai/skills/blob/main/skills/.curated/playwright/SKILL.md)，定位和修复可参考 Superpowers 的 systematic-debugging、test-driven-development。按项目需要使用，避免增加重复框架。

## 问题处理与交付

- 阻塞性问题和小问题：直接做必要修复，补回归用例，并在报告记录复现、原因、修改和验证结果。
- 其他问题：整理可复现的问题报告和回归用例，交给负责同学修复。
- 测试仅针对本地/隔离的项目实例与测试数据；保留现有未提交修改。
- 交付测试代码、需求—用例对照表、执行报告与证据，明确通过、失败、未执行和剩余缺口。每个缺陷关联需求、最小复现、命令、预期/实际结果和处理状态。
