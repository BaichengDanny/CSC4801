## 基线问题

1. **同名雇主的时段会混入候选人列表**（FP-SCHED-2）。让两个演示雇主用同一个公司名称，以只有其中一方邀请的候选人打开 Interviews。另一雇主的时段出现在可选列表中，提交后服务端返回 `403`，页面提示该时段必须属于申请的雇主。未观察到跨雇主预约成功。候选人端用公司名比较，服务端用雇主 ID。应在响应中使用稳定雇主 ID 或提供按申请过滤的时段。位置：[候选人过滤](../candidate/assets/matchwork.js#L237)、[职位响应](../recruiting/present.py#L58)、[服务端预约](../recruiting/scheduling.py#L83)。
2. **超过两周的未预约时段可以创建，雇主无法在页面撤回**（FP-SCHED-1）。在 11 月 25 日，用 “Add a specific time” 新建 12 月 20 日 09:00–09:30 PT。页面报告成功，候选人能选到，雇主刷新后仍只能选择未来 14 天，找不到该时段的移除按钮。删除 API 可以正常删除无预约时段。页面需要能导航到该日期或列出全部未来时段。位置：[14 天日期范围](../recruiter/interviews.html#L206)、[自定义时间提交](../recruiter/interviews.html#L349)。
3. **职位校验失败仍写入数据**（FP-EMP-2、FP-TEST-1）。在隔离 API 测试中，发送有效的职位标题和描述并把地点设为 121 字符。创建返回 `400`，候选人随后仍能看到新增职位。编辑时一起修改标题和超长地点也返回 `400`，候选人仍看到新标题。核心字段先提交，附加字段在第二次写入前校验。应在一个事务中验证和写入，增加失败后无变更的回归测试。位置：[创建及编辑路由](../recruiting/api.py#L253)、[附加字段验证](../recruiting/api.py#L56)。
4. **时区口径不一致**（FP-SCHED-1、FP-PROC-1）。候选人页面固定写 `UTC−8`，实际用 `America/Los_Angeles`。用生产页面采用的 `Intl` 格式化设置验证，2027-07-15 16:00 UTC 显示为 09:00、GMT−7。API 也接受无偏移量的时间并按运行环境的本地时区转换，尽管项目规格宣称要求带时区的 ISO 时间。应统一文档和页面显示，并让 API 拒绝缺少偏移的时间或明确约定其含义。位置：[候选人时区标签](../candidate/interviews.html#L170)、[时区设置](../candidate/assets/matchwork.js#L45)、[API 时间转换](../recruiting/api.py#L337)。
5. **职位详情会把所有申请 `409` 显示成已申请**（FP-CAN-3）。源码核对表明，已关闭的职位仍显示 Apply，服务端返回 `409` 并拒绝创建申请，详情页处理器却把按钮切到 Applied。这一项通过 API 已有的关闭职位用例和前端分支核对，未另外执行该浏览器场景。应只在已确认存在申请后显示 Applied。位置：[详情页处理器](../candidate/assets/matchwork.js#L416)、[服务端关闭规则](../recruiting/jobs.py#L129)。
6. **XSS 测试覆盖停在 JSON 层**（FP-SEC-3、FP-TEST-1）。现有测试确认字符串在 JSON 中作为数据返回，并且不出现在静态 HTML 或其他角色的响应里。实际 DOM 由 JS 渲染，课程要求测试渲染或清理逻辑，当前测试没有调用这些代码。本次源码审查看到多个页面使用 `esc`，验收发现的是缺少所要求的证明。位置：[当前测试](../tests/unit/test_web.py#L33)、[前端渲染](../candidate/assets/matchwork.js#L335)。
7. **简历的跨人地址 `403` 契约缺少直接证据**（FP-CAN-1、FP-SEC-1）。候选人 API 由登录会话确定访问自己的资料，无按 ID 读写简历的 HTTP 路由。服务层已测跨人访问返回 `403`，HTTP 测试也确认另一候选人与雇主的响应都没有原简历。若按课程原文验收特定简历的直接 URL/API 请求，需要明确对应入口或请课程方确认接受这种仅对当前账号开放的 API 结构。

## 三项修复复测

同日根据用户指定范围，在本地修复 FP-SCHED-1、FP-SCHED-2 和 FP-EMP-2。上面的表记录修复前的审计基线。

- **FP-SCHED-1**：雇主创建未来数月的 09:05–09:35 PDT 时段，刷新后在日历找到并撤回，二次刷新确认删除。浏览器拒绝夏令时切换当天不存在和重复的时间。API 测试拒绝无偏移、非整秒、结束早于开始和超出 UTC 可表示范围的时段。
- **FP-SCHED-2**：同名雇主有两个不同时间，候选人只看到所属雇主的时段。这个时段挂在同一雇主的另一职位下，成功预约后雇主界面可见。
- **FP-EMP-2**：创建校验失败后没有新增职位。编辑时只要附加字段校验失败，标题、描述、技能与其他字段都保留原值。浏览器正常发布、编辑及刷新后读取均成功。
